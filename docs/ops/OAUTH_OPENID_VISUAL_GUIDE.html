02

OAuth 是什么

一句话：用“受控的令牌”代替“把密码交给第三方”。

OAuth 2.0 = 授权委托

客户端拿到 access_token，按 scope 访问资源。token 不证明“你是谁”，只证明“被允许做什么”。

access_tokenscopeexpires_in

OpenID Connect = 身份层

在 OAuth 之上加一个 id_token（JWT）。它回答“你是谁”，并带 nonce 防重放。

id_tokenopenidnonce
问题OAuth 2.0OpenID Connect
回答什么能不能访问、能访问多少你是谁、何时登录、给哪个应用
核心产物access_tokenid_token（JWT）+ access_token
典型用途调用 API、机器对机器“使用 Microsoft 登录”
校验重点scope、aud、过期时间签名、iss、aud、exp、nonce、sub
不要用 access_token 当登录凭证。它可能只代表“允许读通讯录”，不代表“这是谁”。登录请校验 id_token。

04

授权码流程

浏览器只经手 code；code 一次性、短寿命；换 token 必须带 secret。

例子 / 授权请求
GET /authorize?response_type=code&client_id=...&redirect_uri=https%3A%2F%2Fexample.com%2Fauth%2Fexternal%2Fcallback&scope=openid%20profile%20email&state=...&nonce=...
例子 / 换 token
POST /token
grant_type=authorization_code&code=...&redirect_uri=...&client_id=...&client_secret=... 
// 换 token 的响应（字段因 IdP 而异）
{
  "token_type": "Bearer",
  "expires_in": 3600,
  "access_token": "eyJ0eXAi...",
  "id_token": "eyJhbGci...",
  "refresh_token": "0.AXoA...",
  "scope": "openid profile email"
}
回调三件事：校验 state 与 Cookie 一致；用 code 换 token；校验 id_token。任何一步失败都不要建立会话。
05

PKCE

公共客户端没有 secret，就用“一次性证明”防止授权码被截获。

生成

// 浏览器 Web Crypto
const verifier = base64url(crypto.getRandomValues(new Uint8Array(32)));
const digest = await crypto.subtle.digest("SHA-256", enc.encode(verifier));
const challenge = base64url(digest);

规则

  • code_challenge_method=S256，不要用 plain
  • verifier 43–128 字符，只在本机保存
  • iOS/Android 用系统浏览器 + 自定义 scheme
  • 回调后立即清除 verifier

{
  "iss": "https://login.microsoftonline.com/{tenantid}/v2.0",
  "sub": "AAAAAAAAAAAAAAAAAAAAAIkzqFVrSaSaFHy782bbtaQ",
  "aud": "9cc43201-13ac-4f7e-8a24-bf3a02e80e4a",
  "exp": 1761792000,
  "iat": 1761788100,
  "nonce": "0e406d9ccbe36182c819b5db76dc7f76",

  "name": "Fausto Feng",
  "tid": "9188040d-6c67-4c5b-b112-36a304b66dad"

claim用途注意
sub稳定用户 ID只存哈希；不要用 email 当主键
aud目标应用必须等于你的 Client ID
iss签发者/common 时按 tid 校验模板
nonce防重放必须与发起时完全一致
email展示 / 默认值不要用于自动关联账号
例子 / discovery
GET https://login.microsoftonline.com/common/v2.0/.well-known/openid-configuration
返回 authorization_endpoint、token_endpoint、jwks_uri、issuer。不要硬编码端点。
07

刷新令牌

短寿命 access_token + 长寿命 refresh_token；refresh 只放 HttpOnly Cookie 或服务端。

// 刷新请求
POST /token
grant_type=refresh_token&refresh_token=...&client_id=...&client_secret=...
并发刷新会互相踢下线。多标签页共享刷新结果，或用后端单飞（single-flight）合并并发的刷新请求。
08

客户端凭证

没有用户，只有应用身份；不要拿它当“登录”。

# curl 示例
curl -X POST https://idp.example.com/oauth2/token \
  -d grant_type=client_credentials \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d scope=api://sim-api/.default
适用：定时任务、CI、服务间 API。令牌里没有用户，审计只能追到“哪个应用”。

10

接入业务系统：八步

从注册应用走到上线回归，顺序不要颠倒。

注册应用平台选 Web（服务端换 token），Redirect URI 写完整路径，精确匹配。
对齐受众与 Authority个人账号 /consumers；单租户 /{tenantId}；全部 /common。
密钥入密钥库Client Secret 不进仓库；生产用文件密钥/环境变量。
后端发起授权生成 state、nonce，写加密 HttpOnly Cookie，302 到授权端点。
回调换 token校验 state → code 换 token → 验签/iss/aud/exp/nonce。
身份映射sub 哈希查绑定；未绑定走注册或拒绝。
建立本地会话签发自己的 JWT/刷新令牌；不要把 IdP token 存 localStorage。
安全与回归重放、过期、错 state、错 nonce、解绑、2FA 全部回归。

后端校验（伪代码）

var state = await stateStore.ConsumeAsync(providerId);
var tokens = await ExchangeCodeAsync(code, state.CallbackUrl);
var principal = await ValidateIdTokenAsync(
    tokens.IdToken, authority, clientId, state.Nonce);
var key = Sha256(providerId + ":" + principal.Sub);
var binding = await db.ExternalLogins.FindAsync(providerId, key);
if (binding == null) return RegistrationOrReject();
return IssueLocalSession(binding.UserId);

绑定表（PostgreSQL）

create table system_external_login (
  id uuid primary key,
  provider varchar(32) not null,
  provider_key varchar(64) not null, -- sha256("microsoft:"+sub)
  user_id uuid not null,
  created_at timestamptz not null default now(),
  unique (provider, provider_key)
);

如果改用 ASP.NET Core 内置处理器

builder.Services.AddAuthentication()
  .AddOpenIdConnect("Microsoft", o => {
    o.Authority = "https://login.microsoftonline.com/common/v2.0";
    o.ClientId = cfg["ExternalLogin:Microsoft:ClientId"];
    o.ClientSecret = cfg["ExternalLogin:Microsoft:ClientSecret"];
    o.CallbackPath = "/signin-microsoft";
    o.ResponseType = "code";
    o.UsePkce = true;

使用 /common 时 issuer 带租户 GUID，需按 tid 校验或配置模板；Sim 选择自研后端代理以统一五家 Provider 的登录/绑定流程。

安全清单

上线前逐条打勾；漏一条就可能被重放或接管。

协议层

  • Redirect URI 完全一致，不用通配符
  • state 一次性、随机、与 Cookie 绑定
  • nonce 精确匹配 ID Token
  • 校验 iss / aud / exp，允许 5 分钟时钟偏差
  • 只信 sub，不用 email 自动关联
  • 公共客户端必须 PKCE

会话与密钥

  • token 不放 URL、localStorage、日志
  • 刷新令牌 HttpOnly + Secure + SameSite
  • Secret 只存密钥库，定期轮换
  • state Cookie 路径限定、加密、短期
  • 绑定/解绑需要已登录会话 + 意图校验
  • 本地 2FA 不被第三方登录绕过
攻击防线失败表现
授权码截获PKCE / 机密客户端invalid_grant
CSRF 回调state + HttpOnly Cookiestate 无效 / 过期
ID Token 重放nonce 精确匹配nonce mismatch
账号接管sub 哈希绑定，邮箱不自动关联要求重新绑定
Secret 泄漏密钥库 + 轮换 + 最小权限invalid_client

错误速查

先看错误码，再查这四类：回调、受众、密钥、时效。

错误常见原因修复
AADSTS50011redirect_uri 与注册值不一致逐字符对齐（协议/端口/路径/结尾斜杠）
AADSTS7000215Client Secret 错误或已过期重新生成并更新密钥文件
AADSTS65001用户/管理员未同意权限管理员同意或调整 scope
invalid_request（/common）应用受众是 Consumer，却用了 /common改应用受众为 All，或 Authority 改 /consumers
invalid_grantcode 过期/重复使用、PKCE 不匹配重新发起授权；检查 verifier
state invalidCookie 丢失、过期、已消费不要刷新旧回调；重新发起
nonce mismatch多标签页并发或重放每次发起独立 state/nonce
登录后仍 401只拿到 access_token，没建本地会话校验 id_token 后签发本地 JWT
Microsoft 受众矩阵：个人 /consumers；组织多租户 /organizations；单租户 /{tenantId}；组织 + 个人 /common。应用注册的 Supported account types 必须与 Authority 匹配。
