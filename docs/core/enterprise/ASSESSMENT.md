# 企业级框架优化评估（待确认）

评估日期：2026-07-28。

本文只记录基于当前仓库的优化建议，不代表已经批准实施。除本次需求明确指定的文件能力、存储适配、接口限流、前端组件和文档外，以下优化均保持“待用户确认”；实施前必须先说明范围、收益、风险、迁移方式和验证计划，并取得确认。

## 已形成的基础能力

- framework 已提供与业务模块解耦的文件存储端口，内置本地文件、数据库、Amazon S3、腾讯云 COS 和阿里云 OSS 适配器。
- framework 已提供 Scriban 文本模板渲染、CSV/JSON/HTML 导出、LibreOffice Office-to-PDF 转换，以及 ImageMagick 服务端裁剪/压缩端口。
- Web 已提供可复用的 `FileWorkbench` 和共享头像弹窗 `AvatarEditor`。前者处理上传与 Office-to-PDF，后者在浏览器 Canvas 中完成 1:1 裁剪、缩放和 WebP 压缩，桌面与手机 Web 共用同一交互。
- Host 已提供 `[RateLimit]`：无参数时使用配置文件默认配额，传入参数时覆盖默认值；审批目录、外部登录、文件处理和认证接口提供了示例与集成测试。
- 六组 OpenAPI 当前契约已进入生成链路；本次 Web 101 项单元测试断言通过，但 Windows 工作区读取依赖文件时出现一次 `EPERM`；后端 75 项测试中 74 项通过。依赖许可证清单已随当前直接依赖修复，剩余 1 项与本次通知平台无关：英文业务错误本地化资源未被测试 Host 正确发现。System OpenAPI 已重生成并通过 v1 兼容测试，其他历史契约仍需按 CI 命令执行全量漂移验证。
- 业务内容文件已有 provider 无关稳定 ID；通用资源策略把所有者、公开/私有和文件引用拆分建模，已支持所有者可见和显式受控分享，后续项目管理可复用同一端口。

## 2026-07-28 前后端工程化复核

结论：当前仓库的分层和工具链设计符合“模块化单体 + 前后端分离”的企业级工程方向，但当前提交状态尚不满足“所有交付门禁全绿”的完成定义。此次复核未发现需要推翻现有技术栈或新增大型依赖的理由；应先修复下面列出的既有门禁漂移，再宣称达到可持续交付基线。

- 后端：.NET SDK、中央 NuGet 版本、Windows/Linux 锁文件、许可证/漏洞检查、六组 OpenAPI 漂移与兼容检查、架构依赖测试、完整 Host 集成测试、显式迁移、健康探针、结构化日志、SBOM 和非 root/只读容器门禁均已形成；业务模块继续只依赖稳定 Contracts，System 的资源访问实现没有让 framework 反向依赖业务模块。
- Web：Node/pnpm 版本、可信锁文件、构建脚本白名单、TypeScript、零警告 ESLint、Vitest、Playwright、OpenAPI 类型生成、生产构建与包体预算均已进入 Jenkins；本次类型检查和 101 项 Vitest 全部通过，编辑器能力复用统一 Axios 与 i18n，没有创建第二套认证/请求链。但全仓 ESLint 当前仍被 Cron 编辑器/计算工具的 7 个既有错误阻断，不能表述为“零警告已保持”。
- 数据与安全：私有资源按所有者过滤管理查询，资源关联的托管文件与访问策略同步；显式分享链接支持有效期和指纹去重，访问审计记录账号/指纹哈希、IP、UA 和时间。无权限文件按不存在响应。上线仍需执行数据库备份、受控迁移和历史分享数据清理，并在真实对象存储、反向代理和浏览器环境完成越权 E2E。
- 尚未闭环：先处理 OpenAPI 可重生成性、许可证审核清单、本地化测试 Host 和 Cron ESLint 四项现有门禁；首次容器 CI 实跑证据、真实对象存储兼容/故障测试、多实例共享限流、版本化数据库迁移、集中指标/Trace/SLO、分享链接主动撤销管理界面仍属于后续治理项。

## 建议审批顺序

1. 先确认三个 P0：上传安全、转换 Worker 隔离、多实例共享限流。
2. 评审 `docs/design/scheduling/SCHEDULE_TASK_DESIGN.md`（通用库）与 `docs/design/scheduling/SCHEDULE_TASK_SIMFRAMEWORK_INTEGRATION.md`（SimApp 集成层），决定是否按通用库 P0–P7 + 集成层 I0–I9 阶段落地定时任务自研替换。
3. 再根据真实部署方式确认对象直传、租户隔离、韧性和可观测性。
4. 最后按产品体验决定模板治理和高级图片交互。

确认某项后，应先补 ADR/威胁模型和验收标准，再实施代码，不把本表的建议直接视为授权。
