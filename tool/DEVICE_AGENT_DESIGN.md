# 设备接入 Agent（多设备：串口/TCP/文件 → WebSocket）设计方案

>
> 设计日期：2026-11-16
>
> 桌面端设计：[`DEVICE_AGENT_UI_DESIGN.md`](DEVICE_AGENT_UI_DESIGN.md)（WinUI3 一体化托盘宿主、数据源配置管理、JS 解析脚本与开机启动；宿主外壳 P0 已实施，P1 页面未实施）。
>
> 适用范围：新增根级 `tool/` 目录；与 `api`、`web` 的集成边界见第 12 节。

> 结论：以一个 .NET 10 Worker Service 形态的通用 Agent，在一台上位机上并行承载多台不同设备（电子秤、焊线拉力测试、Die 焊接推力测试、数据文件型设备等）。每台设备绑定独立的串口、TCP 连接或文件目录，拥有独立的数据通道、解析器和队列；解析器可以是内置规则或按设备交付的插件。数据统一转为 WebSocket 消息，同时提供本机 WebSocket 服务端（工位页面直连）与中心 WebSocket 客户端（数据进平台）两种出口。单设备离线、解析失败或插件崩溃不影响其他设备；业务判定仍留在平台与前端。

## 1. 背景与目标

### 1.1 背景

- 浏览器不能直接访问系统串口或原始 TCP；Web Serial 受浏览器种类、HTTPS、用户授权和页面生命周期限制，不适合作为产线主方案。
- 现场设备的连接位置不固定：电子秤通常接工位 PC 的 USB 转串口；拉力测试机可能接工位 PC、串口服务器，或只提供 Windows SDK/DLL。
- 同一台上位机可能连接多台设备：例如一台焊线拉力测试机、一台 Die 焊接推力测试机，再叠加电子秤或文件导出型设备。各设备的接口（串口/TCP/文件/SDK）、帧格式和解析规则都可能不同，需要并行采集并保持设备间隔离。
- 部分设备不提供实时接口，而是在测试完成后把结果写成 CSV、TXT、XML 或 Excel 文件放到设备专属目录（本机或网络共享），需要文件监听、完成判定和格式解析。
- 设备格式差异大：通用规则无法覆盖全部厂商私有格式，解析器需要按设备插件化交付，避免每次新增机型都修改主程序。
- 每个项目重复实现串口读取、断线重连、帧解析、数据上传，成本高且质量不一致。
- 需要一个通用的采集转发程序，把「设备侧接口差异」收敛在 Agent 内，对上层暴露统一的数据契约。

### 1.2 目标

1. **多源接入**：串口、TCP 客户端、TCP 服务端、UDP、文件目录（新增文件、追加文件和整文件读取），预留 HTTP 轮询和厂商 SDK 插件。
2. **多设备并发与隔离**：一台上位机同时运行多个设备通道，每台设备独立配置源、解析器、汇与缓冲；单设备离线、解析失败或插件崩溃不影响其他设备。
3. **多汇出口**：本机 WebSocket 服务端、中心 WebSocket 客户端、HTTP/MQTT 批量上传，支持一个或多个设备共用一个出口，也支持按设备独立配置。
4. **配置驱动**：一条设备通道描述「设备 + 源 + 解析器 + 汇」，新增设备类型不修改主程序。
5. **解析器插件化**：通用格式使用内置解析器；厂商专有二进制、复杂 CSV/XML/Excel 或依赖 SDK 的格式以独立插件交付，不同设备可使用不同插件与版本，可单独升级，故障隔离。
6. **命令事务**：支持「下发指令 → 等待匹配响应 → 超时失败」的请求/应答模式，覆盖拉力测试机一类设备；同一设备通道内命令串行执行。
7. **断线不丢数**：网络中断时本地磁盘缓冲，恢复后按设备按序补传，中心按设备序号与文件记录键去重。
8. **可运维**：单文件可执行、Windows 服务自启动、结构化日志、设备级状态与心跳。
9. **安全默认**：本机监听仅回环地址，来源 Origin 白名单；单机模式令牌可留空、不启用 TLS，作为可选能力保留令牌与 `wss`；第三方解析器在隔离进程中运行。

### 1.3 非目标

- 不做「万能协议识别」。帧边界、文件格式与语义必须按设备配置或编写解析插件，不承诺零配置兼容任意设备。
- 不做文件内容的人工录入或表格编辑器；Agent 只负责读取、解析、转发与归档。
- 不承载业务规则：电子秤稳定判定、超差判定、工单/样品绑定、检验记录生成属于前端或平台业务模块。
- 不做设备间的测试流程编排（如先拉力后推力、设备互锁）；Agent 只采集各设备数据，流程控制由上位机或平台业务承担。
- 不替代浏览器端 Web Serial 方案；Web Serial 可作为独立选项并行存在，但不属于本 Agent。
- 不做设备固件升级、反向下发控制闭环的生产调度（命令事务只服务数据采集所需的查询指令）。
- 不在 Agent 内实现设备台账、权限、审计中心；这些由平台中心网关承担。

## 2. 总体架构

### 2.1 数据面

```text
设备 A ──Serial / TCP / UDP──┐
设备 B ──Serial / TCP────────┼──► Source 注册表（一源一设备）
文件目录 ──文件监听───────────┘            │
                                           ▼
                         多设备通道（每设备独立解析器、队列与状态）
                         ├── PT-01 焊线拉力测试（解析器 A）
                         ├── DS-01 Die 焊接推力测试（解析器 B）
                         └── SC-01 电子秤（内置解析器）
                                           │
                                           ▼
                         Router ──► Sink 出口
                                    ├── ws-server（本机页面）
                                    ├── ws-client（中心网关）
                                    ├── http-batch / mqtt（可选）
                                    └── disk spool（按设备分区）
```

- **Source**：物理或网络接口定义，负责连接建立、重连、热插拔和原始字节读取；一个源实例只服务一台设备。
- **Channel**：一台设备的数据处理管线，绑定 `deviceId`、源引用、解析器与出口。
- **Codec**：每设备独立，负责帧/记录切分和可选语义解析，输出原始帧 + 解析结果；内置规则或设备插件。
- **Router**：按 `deviceId`、`channelId`、`deviceType` 与订阅关系分发，记录每设备序号、时间戳和统计。
- **Sink**：负责对外传输；出口可被多个设备共享，每个出口内部按设备分区队列，一个设备或一个汇故障不影响其他设备与出口。

隔离原则：每台设备一条独立处理管线、独立源和有界队列；单设备断线、解析慢、队列满或插件崩溃不得阻塞其他设备。

### 2.2 控制面

- 本地管理 HTTP API：设备与通道列表、每设备状态与最后数据时间、启停、指令下发、配置重载。
- 配置校验与热加载：先校验后应用，失败保留上一份有效配置并上报告警事件。
- 结构化日志与本地滚动文件；默认只记录元数据，原始载荷仅在显式开启调试时记录。

### 2.3 部署拓扑

| 拓扑 | 数据路径 | 适用 |
| --- | --- | --- |
| 工位本机 | 设备 → 工位 PC 上的 Agent → 页面直连 `ws://127.0.0.1:<port>` | 电子秤录入、单工位看板 |
| 中心直采 | 设备/串口服务器 → Agent → `wss://<中心>/device-gateway` → 平台 | 拉力测试机结果自动进 QMS/MES |
| 混合双出口 | 同一通道同时发本机页面与中心网关 | 操作员实时查看 + 平台留痕 |
| 文件直采 | 设备导出文件 → 设备专属目录（本机或网络共享）→ Agent 文件通道 → 页面与中心 | 测试机按批次导出结果文件、无实时接口 |
| 多设备上位机 | 同一上位机连接拉力测试、Die 推力测试等多台设备，Agent 按设备拆分通道与解析器 | 一台上位机多机型、多接口混合 |

## 3. 核心模型与配置

### 3.1 概念

| 概念 | 说明 |
| --- | --- |
| Agent | 一个进程实例，对应一台上位机或采集机；拥有唯一 `agentId`（默认取首次安装时的主机名，见 3.4），可承载多台设备 |
| Source | 物理或网络接口定义（COM3、`tcp://`、目录等）；一个源实例只对应一台设备 |
| Device | 一台实际测试设备，含 `deviceId`（平台设备编号/编码，见 3.4）、`deviceType`（`scale`/`pullTest`/`dieShear` 等）与显示名 |
| Channel | 一台设备的数据处理管线，绑定 `deviceId`、源引用、解析器与出口；`channelId` 全局唯一 |
| Codec | 每设备独立的帧/记录切分与解析规则，可为内置（直通、分隔符、定长、正则、CSV、Modbus）或解析插件 |
| Parser Plugin | 以独立程序集与进程交付的设备专有格式解析器，按清单注册，可单独升级 |
| Sink | 出口定义，可被多个设备通道共享；每个出口内部按设备分区缓冲与重试 |
| Spool | 中心出口的本地磁盘缓冲，按设备分区、按序补传并等待确认 |

拓扑关系：一个 `agentId` 对应一台上位机，可包含多个设备通道；每台设备使用独立的串口、TCP 连接或文件目录，不共用链路。因此源与设备固定 1:1，不做帧级分流。

### 3.2 配置示例

```json
{
  "agent": {
    "id": "LINE-A-PC01",
    "displayName": "A 线测试上位机",
    "localWs": { "enabled": true, "bind": "127.0.0.1", "port": 18080,
                 "allowedOrigins": ["https://qms.example.com"] }
  },
  "sources": [
    { "id": "com3-pulltest", "type": "serial", "port": "COM3", "baudRate": 9600,
      "dataBits": 8, "parity": "None", "stopBits": "One" },
    { "id": "com4-dieshear", "type": "serial", "port": "COM4", "baudRate": 19200,
      "dataBits": 8, "parity": "Even", "stopBits": "One" },
    { "id": "dir-pulltest", "type": "file", "directory": "D:/device/in",
      "pattern": "PT02_*.csv", "stableSeconds": 5,
      "archiveDirectory": "D:/device/archive", "errorDirectory": "D:/device/error" }
  ],
  "sinks": {
    "local": { "type": "wsServer" },
    "center": { "type": "wsClient", "url": "wss://qms.example.com/api/device-gateway",
                "credentialRef": "LINE-A-PC01",
                "spool": { "maxMb": 2048, "maxDays": 7 } }
  },
  "channels": [
    { "id": "pt-01", "deviceId": "PT-001", "deviceType": "pullTest",
      "deviceName": "焊线拉力测试机 01", "sourceRef": "com3-pulltest",
      "codec": { "type": "delimiter", "delimiter": "\r\n", "encoding": "ascii",
                 "parse": { "type": "regex", "pattern": "^RESULT,FORCE=(?<force>\\d+\\.\\d+)N" } },
      "sinks": ["local", "center"] },
    { "id": "ds-01", "deviceId": "DS-001", "deviceType": "dieShear",
      "deviceName": "Die 焊接推力测试机 01", "sourceRef": "com4-dieshear",
      "codec": { "type": "plugin", "pluginId": "vendor-dieshear", "version": "1.0.0" },
      "sinks": ["center"] },
    { "id": "pt-02-file", "deviceId": "PT-002", "deviceType": "pullTest",
      "deviceName": "焊线拉力测试机 02（文件导出）", "sourceRef": "dir-pulltest",
      "codec": { "type": "csv", "csvDelimiter": ",", "encoding": "utf-8", "hasHeader": true,
                 "columns": { "sampleId": "Sample", "force": "ForceN" } },
      "sinks": ["center"] }
  ]
}
```

一个 `sourceRef` 只能被一个设备通道引用，即“一源一设备”；启动校验不通过时拒绝应用整份配置。示例展示目标配置；`center`/`wsClient` 已实现，`plugin` 解析器仍属后续阶段。可运行字段以 [`agent.example.json`](agent.example.json)、[`agent.center.example.json`](agent.center.example.json) 和 [`README.md`](README.md) 为准，差异见第 17 节。

示例中的 `agent.id` 为显式配置值；未配置时默认取首次安装时的机器名，`agentId` 与 `deviceId` 的命名规则见 3.4。

### 3.3 配置管理

- 以本地 `agent.json` 为唯一运行时事实，文件监听热加载；当前实现是校验通过后停止全部通道/出口并按新配置重建，设备序号与 spool 保留，重载期间所有设备短暂中断。后续可按设备通道粒度增量应用。
- 校验规则：`agentId`/`channelId`/`deviceId` 唯一；一个源只能绑定一个通道；Sink 引用有效；超时与缓冲参数在允许范围。
- 不可热改字段：`agent.id`、`agent.stateDirectory`、本机监听 `enabled`/`bind`/`port` 和托盘启用状态；修改时拒绝重载并提示重启。
- 应用策略：校验全部通过后应用；失败时保留上一份有效配置，错误写入 `/api/status` 的 `config.lastError`。
- 中心统一下发（P2）只覆盖「期望配置」，Agent 保留本地 `base` 与下发 `override`，断网时继续运行最后有效配置。
- 敏感值不写入日志；凭据通过 `credentialRef` 引用本机加密存储，不放在配置文件明文里。

### 3.4 身份与命名约定

#### agentId

- 默认值：首次安装时读取操作系统主机名（.NET `Environment.MachineName`）并写入本地配置（敏感值另行加密存储），之后固定使用；`agent.id` 可显式覆盖默认值。
- 身份与展示分离：`agentId` 是稳定身份；心跳与状态另带 `hostName` 展示当前主机名。
- 主机名变更：检测到与首次记录不一致时上报 `agent.hostnameChanged` 事件，要求重新注册或迁移，不自动修改 `agentId`。
- 唯一性：平台按 `agentId` 注册；主机名重复（克隆镜像、默认 `DESKTOP-XXXX`）时拒绝注册，要求显式覆盖或加后缀。
- 字符与长度：建议 `[A-Za-z0-9._-]`，长度上限 64；平台按不区分大小写比较，展示保留原值；主机名含其他字符时必须显式配置合法 `agent.id`。

#### deviceId

- 取值：使用平台设备台账中的设备编号/编码（如 `PT-001`、`DS-002`），不使用 `COM3` 等接口名或自增整数；纯数字编号必须加设备类型前缀或采用「类型-编号」复合。
- 唯一性：同一 `agentId` 下唯一，平台按 `agentId + deviceId` 登记；禁止仅大小写不同的两个 ID。
- 稳定性：设备更换但编号不变时数据保持连续；硬件序列号写入设备元数据或解析结果用于追溯，不作为设备身份。
- 多工位：同一台设备有多个测试工位时使用后缀（如 `DS-001-S1`）或后续增加 `stationId`（见 Q-10）；一个 `deviceId` 同时只能绑定一个活动通道。
- 变更：投用后不可随意修改；确需变更按「新设备登记 + 历史数据保留在原 ID」处理，平台不自动迁移历史序号。

## 4. 源适配器

| 类型 | 关键参数 | 行为与注意点 |
| --- | --- | --- |
| `serial` | 端口、波特率、数据位、校验、停止位、编码、DTR/RTS | Windows 下独占，串口助手等程序必须先关闭；定时扫描 USB 热插拔；一个串口只对应一台设备 |
| `tcpClient` | 地址、端口、重连退避、心跳 | 适用于串口服务器（RS-232/485 → 以太网）；一个 TCP 连接只对应一台设备；指数退避重连，半开连接由心跳或读超时判定 |
| `tcpServer` | 监听地址、端口、最大连接数 | 设备主动连入时使用；允许多台设备分别建连，每个连接绑定一台设备并对应独立通道，不做帧级分流 |
| `udp` | 绑定地址、端口、远端白名单 | 无连接语义，按帧到达即产出；一个绑定端口只对应一台设备；只接受白名单远端，防止噪声 |
| `file` | 监听目录、文件名模式、读取模式、完成判定、归档策略、编码 | 适用于设备导出 CSV/TXT/XML/Excel 的场景；一个目录只对应一台设备；写入未完成前不得读取；按文件哈希与文件名去重；处理结果分归档/错误目录 |
| `httpPoll` | URL、间隔、请求头、响应解析 | P2 预留，用于只提供 HTTP 接口的设备或网关 |
| `plugin` | 插件标识、位数、启动参数 | 厂商 SDK/DLL 的宿主；独立进程通过 stdio JSON-RPC 通信，崩溃不拖垮主进程，x86/x64 位数独立 |

源适配器统一接口语义：启动、停止、状态事件、字节流输出、可选命令写入。所有连接类源适配器都必须实现断线检测与重连，不允许出现「端口已断但状态仍为 connected」。

连接边界：

- 一个源实例只对应一台设备；`tcpServer`（后续）每个连接对应一台设备，每个连接独立绑定通道。
- 若现场确有一条物理链路承载多台设备（RS-485 多从站、上位机把多个工位聚合进一个 TCP 流），应由设备侧网关/前置采集器先拆分；Agent 核心模型不做帧级 `demux`，避免猜错设备归属。
- 源断线、解析阻塞或队列满只影响对应设备；不同设备使用独立源和有界队列。

文件源补充约定：

- 完成判定：默认要求文件大小与最后写入时间稳定 N 秒（默认 5 秒）；设备支持时优先使用 `.done` 伴生文件或原子重命名。
- 监听可靠性：`FileSystemWatcher` 只作为加速信号，必须叠加周期扫描（默认 30 秒），避免网络共享或事件丢失漏文件。
- 读取模式：`wholeFile` 交给解析器按文件解析；`line` 按行/记录切分后逐条产出；`tail` 用于持续追加的日志型文件。
- 大文件：流式读取，配置单文件大小上限、记录数上限与解析超时；超限进入错误目录并告警。
- 幂等：处理前记录 `文件名 + 大小 + SHA-256 + 记录序号`，重启或重复投递不产生重复业务记录；归档移动不是唯一处理标记。
- 安全：拒绝目录穿越与符号链接逃逸；共享目录凭据由服务账户或凭据引用提供，不写入配置文件明文。

## 5. 编解码与命令事务

### 5.1 帧边界

对于文件源，Codec 负责「记录切分」：整文件交给解析插件，或按行/记录分隔拆成多条记录。

| 类型 | 说明 |
| --- | --- |
| `passthrough` | 读缓冲区或整个文件即一帧，仅用于数据块语义明确的设备 |
| `delimiter` | 以 `\r\n`、`\r`、自定义字节序列切帧，最常见于电子秤 |
| `csv` | 带表头/列映射的 CSV 记录切分，适用于设备导出文件 |
| `fixedLength` | 定长帧，适合固定格式仪表 |
| `lengthPrefix` | 1/2/4 字节长度头 + 载荷，适合私有二进制协议 |
| `stxEtx` | 以 STX/ETX 包裹并支持转义，适合部分老设备 |
| `modbusRtu` / `modbusTcp` | P2 提供，支持轮询读取寄存器作为通道数据源 |
| `script` | P2 提供，受限脚本实现自定义切帧与解析；其中“分隔符切帧 + JS 解析”由 WinUI3 桌面端阶段先行实施，见 [`DEVICE_AGENT_UI_DESIGN.md`](DEVICE_AGENT_UI_DESIGN.md) |

### 5.2 解析与容错

- 每帧同时保留 `raw`（Base64）与可选的 `text`、`parsed`；解析失败的帧仍然产出，附 `parseError` 与原始内容，便于现场排查。
- 编码默认按配置的 ASCII/UTF-8/GBK 解码；二进制设备只输出 Base64。
- 单帧大小上限默认 64 KiB，超限丢弃并产生事件计数，不阻塞后续帧。
- 解析异常只影响当前帧，不改变通道状态；连续解析失败达到阈值时产生 `channel.degraded` 事件。

### 5.3 解析器插件化

- 插件种类：`parser`（帧/文件解析）与 `source`（厂商 SDK 源）统一由 `Sim.DeviceAgent.PluginHost` 托管；首个版本先实现 `parser`。
- 设备绑定：每台设备独立选择解析器与版本，例如拉力测试使用 `vendor-pulltest@1.2`、Die 焊接推力测试使用 `vendor-dieshear@2.0`，两者互不影响。
- 契约输入：设备标识与类型、通道标识、编码、原始字节或文件流、文件元数据（名称、大小、SHA-256）、解析选项；契约输出：`DeviceRecord` 列表（解析结果、可选原始片段、`recordIndex`、可选设备时间）。
- 运行方式：独立进程，通过 stdio JSON-RPC（命名管道可选）与主进程通信；主进程不加载第三方 DLL，插件崩溃只使当前设备通道进入 `degraded` 并自动重启，不影响其他设备。默认每设备通道独立插件进程；资源评估通过后可配置共享进程，但共享进程崩溃会影响引用它的设备。
- 设备归属：解析器只处理其所属设备通道的帧或文件，不得输出其他设备的数据；若上游确实聚合了多台设备，先由网关拆分后再接入。
- 批量边界：高频帧按 50 ms 或 100 条聚合后批量交给插件，避免逐帧 IPC；文件解析支持流式输入，避免整文件驻留内存。
- 插件清单：`id`、`version`、`apiVersion`、`kind`、支持的 `deviceTypes` 与扩展名/魔数、目标平台与位数、入口、SHA-256 与签名。配置以 `pluginId@version` 引用，升级需显式切换版本。
- 交付与测试：每个插件必须附带样例文件与期望输出（golden files），并声明资源上限（内存、CPU 时间、单次解析超时）；插件版本变化时只重启对应设备通道，不影响其他设备。
- 内置与插件的边界：分隔符、正则、定长、CSV、Modbus 等通用格式内置；厂商私有二进制、复杂 Excel/XML 结构、需要调用 SDK 的格式放插件。

### 5.4 命令事务

- 事务模型：`send(payload, timeoutMs, matchRule)` → 成功返回匹配帧，超时返回失败；`requestId` 由调用方生成并在响应中原样返回。
- 默认每通道串行执行事务（同一时刻一个在途请求），排队上限可配；避免对同一设备并发写导致响应错配。
- 匹配规则支持「按分隔符的下一条帧」「正则匹配」「长度 + 命令字匹配」三种；不匹配的帧仍作为普通数据输出。
- 事务与持续输出共存：电子秤这类只读设备只走数据流；拉力机可按「条码查询 → 触发测试 → 读取结果」编排多次事务。
- 事务审计：记录命令、耗时、成功/超时，不默认记录完整载荷。

## 6. WebSocket 消息协议

### 6.1 信封字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `v` | int | 协议版本，当前为 `1` |
| `type` | string | `hello`/`helloAck`/`subscribe`/`data`/`status`/`event`/`command`/`response`/`error`/`ping`/`pong` |
| `agentId` | string | Agent 唯一标识，默认取首次安装主机名（见 3.4） |
| `deviceId` | string | 平台设备编号/编码，作为设备台账主键；同一 `agentId` 下唯一（见 3.4） |
| `deviceType` | string | `scale`/`pullTest`/`dieShear` 等，由通道配置决定 |
| `channelId` | string | 设备通道标识，控制类消息可缺省 |
| `seq` | long | 设备内单调递增，重连与通道重建不清零 |
| `ts` | string | Agent 接收时刻（ISO 8601 带时区）；设备自带时间放 `parsed` |
| `raw` | string | 原始帧 Base64 |
| `text` | string? | 可解码时的文本帧 |
| `parsed` | object? | 解析结果 |
| `requestId` | string? | 事务标识 |
| `sourceRef` | object? | 文件记录来源：`{name, size, sha256, index}`，用于跨重启去重与回溯 |
| `error` | object? | `code`、`message`、`retryable` |
| `state` | string? | 设备通道状态：`connecting`/`connected`/`waiting`/`degraded`/`faulted`/`stopped` |

### 6.2 消息示例

电子秤数据：

```json
{ "v": 1, "type": "data", "agentId": "LINE-A-PC01",
  "deviceId": "SC-001", "deviceType": "scale", "channelId": "sc-01",
  "seq": 1024, "ts": "2026-11-16T08:15:30.123+08:00",
  "raw": "U1QsR1MsKzAwMTIuMzQ1a2cNCg==", "text": "ST,GS,+0012.345kg\r\n",
  "parsed": { "state": "GS", "sign": "+", "value": 12.345, "unit": "kg" } }
```

拉力机事务：

```json
{ "v": 1, "type": "command", "agentId": "LINE-A-PC01",
  "deviceId": "PT-001", "deviceType": "pullTest", "channelId": "pt-01",
  "requestId": "r-20261116-0007", "op": "send",
  "payload": { "text": "READ\r\n", "timeoutMs": 2000, "match": { "type": "regex", "pattern": "^RESULT.+" } } }
```

```json
{ "v": 1, "type": "response", "agentId": "LINE-A-PC01",
  "deviceId": "PT-001", "deviceType": "pullTest", "channelId": "pt-01",
  "requestId": "r-20261116-0007", "ok": true, "seq": 88, "ts": "2026-11-16T08:16:02.501+08:00",
  "text": "RESULT,FORCE=12.34N\r\n", "parsed": { "force": 12.34, "unit": "N" } }
```

Die 推力测试数据（同一上位机、不同解析插件）：

```json
{ "v": 1, "type": "data", "agentId": "LINE-A-PC01",
  "deviceId": "DS-001", "deviceType": "dieShear", "channelId": "ds-01",
  "seq": 512, "ts": "2026-11-16T08:17:10.020+08:00",
  "raw": "AAECAwQ=", "parsed": { "dieId": "D-0231", "shearForce": 8.76, "unit": "N", "result": "PASS" } }
```

文件通道额外产生 `event` 消息：`file.detected`、`file.processed`（含记录数）、`file.failed`（含错误目录位置）。单文件解析出的多条记录按 `sourceRef.index` 升序输出，每条带 `deviceId` 与 `sourceRef` 便于回溯。

### 6.3 本机 WebSocket 鉴权

- 只绑定 `127.0.0.1`，不监听 `0.0.0.0`。
- 浏览器 WebSocket 无法自定义请求头，因此连接后首条消息必须发送 `hello`（含订阅列表；配置了令牌时再带令牌），3 秒内未完成握手则断开。
- 订阅列表支持按 `channelId`、`deviceId`、`deviceType` 过滤；同一页面可只订阅当前工位需要的设备，避免一台上位机多设备的数据混杂。
- 校验 `Origin` 是否在白名单内；浏览器握手一定携带 `Origin`，非浏览器客户端无 `Origin` 时允许连接。
- 单机模式推荐 `agent.localWs.token` 留空，仅依赖回环监听与 Origin 白名单；需要额外边界时再配置静态令牌。P2 可改为 Agent 校验平台 JWT（配置中心 JWKS、issuer、audience）。
- 未完成握手的连接不接收任何数据，也不响应命令。

### 6.4 中心出口

- 本机模式可不启用中心出口；跨机器使用时可配置 `ws://` 或 `wss://`，优先用设备凭据换取短期访问令牌，令牌放在请求头而不是 URL。当前实现为可选静态 Bearer，令牌可留空。
- 心跳与指数退避重连；连接恢复后先补传 spool，再恢复实时发送。
- 中心按 `agentId + deviceId + seq` 去重，允许乱序到达但按设备按序入库；`channelId` 只用于定位管线。

### 6.5 背压与丢弃策略

| 出口 | 队列满时 | 说明 |
| --- | --- | --- |
| 本机 ws-server | 丢弃该设备最旧数据并累加 `dropped` 计数 | 实时预览优先，页面可按设备重新订阅 |
| 中心 ws-client | 写入该设备的 spool 分区，不丢数据 | 该设备 spool 达到配额才拒绝并置 `faulted`，产生告警 |
| HTTP/MQTT | 批量重试 + 按设备 spool 分区 | 与中心出口使用同一缓冲策略 |

所有出口队列按设备再分区：单设备积压、断线或订阅端消费慢只影响该设备，不挤占同一出口的其他设备。

## 7. 可靠性设计

### 7.1 故障恢复矩阵

| 故障 | 行为 |
| --- | --- |
| USB 串口拔出 | 对应设备通道进入 `waiting`，周期扫描端口，重新插入后自动打开并恢复序号 |
| 网线断开 / 中心重启 | ws-client 指数退避重连，数据写各设备 spool 分区，恢复后按设备按序补传 |
| 页面刷新 / 多标签 | 每个连接独立订阅；刷新不影响 Agent 采集，重新 `hello` 即恢复 |
| Agent 进程重启 | 服务恢复策略拉起；每台设备的 `seq` 从 spool 元数据或最后确认序号继续 |
| 配置损坏 | 保留最后有效配置运行，产生 `config.invalid` 事件；管理接口可回滚 |
| 磁盘满 / 只读 | 中心出口进入 `faulted`，停止接收新 spool 数据并保留本机实时出口；产生告警 |
| 设备长时间无数据 | 超过 `expectedSilenceMs` 产生 `channel.silent` 事件，状态转 `degraded` |
| 文件仍在写入 | 等完成判定通过后再读取；超时未稳定产生 `file.pending` 事件 |
| 重复投递/重复扫描 | 按 `文件名 + 大小 + SHA-256 + 记录序号` 去重，不重复产出 |
| 单台设备离线/无响应 | 仅该设备通道进入 `waiting`/`degraded`，其他设备继续采集 |
| 单设备命令超时 | 仅该设备事务失败；其他设备继续 |
| 单设备队列积压 | 仅该设备丢弃实时数据或写 spool；其他设备不受影响 |
| 单设备解析插件崩溃 | 仅该设备插件自动重启；连续失败使该设备降级，其他设备不受影响 |

### 7.2 Spool 设计

- 追加式 JSONL 分段文件，按设备分区（`spool/<deviceId>/`），按大小（默认 64 MiB）或天滚动，总量与保留期可配（示例：单设备 2 GiB / 7 天，全局上限可配）。
- 每行一条消息信封；写入后按策略 flush，进程崩溃最多丢失最后一个未 flush 批次。
- 中心确认到某个 `(deviceId, seq)` 后删除已确认段；补传按设备按段顺序发送，保证单设备有序。
- 链路上按 `agentId + deviceId + seq` 去重；文件记录另按 `sourceRef` 去重，见 7.3。`seq` 按设备单调递增并在 Agent 重启后延续。
- 单设备积压只占用自己的 spool 配额；达到配额时该设备转 `faulted` 并告警，其他设备继续采集与补传。
- spool 只缓冲中心出口的数据；本机实时出口不落盘，避免高频采集放大磁盘写入。

### 7.3 文件处理幂等

- 目录约定：`input/`、`archive/`、`error/` 由配置指定；处理成功后移动原文件到 `archive/`（可按日期分层），失败重试达到上限后移动到 `error/` 并保留原因。
- 处理状态：`file-state.json` 按设备通道维护，记录 `文件名 + 大小 + 修改时间 + SHA-256 + 状态 + 记录数`，启动时重建未完成项；状态文件损坏时按输入目录与归档目录重新比对，宁可重试也不漏处理。
- 一个文件源目录只对应一台设备；设备更换目录时更新 `sourceRef`，不共用目录猜测归属。
- 去重键：文件记录使用 `agentId + deviceId + sha256 + recordIndex`；中心同时保留 `seq`，两套键都可查重。
- 清理：归档目录按保留天数清理（默认 30 天），错误目录需人工确认后清理，Agent 不自动删除错误文件。
- 共享目录：网络共享断开时通道进入 `waiting`，恢复后先补偿扫描再恢复监听；不要把 `FileSystemWatcher` 事件当作唯一事实。

### 7.4 时间与顺序

- `ts` 使用 Agent 接收时刻，要求工位 PC 开启 NTP 时间同步；设备自带时间只作为 `parsed` 字段保留，不用于排序。
- 每设备通道内以 `seq` 排序；跨设备不保证顺序。
- 中心入库同时保留 `ts` 与中心接收时间，便于评估链路延迟。

## 8. 安全设计

| 威胁 | 对策 |
| --- | --- |
| 本机任意网页连接 Agent | 仅回环监听 + Origin 白名单；单机模式可留空令牌，任何本机进程可访问，这是当前接受的边界 |
| 同机其他用户读取串口/配置 | Agent 服务账户最小权限；凭据加密存储（Windows DPAPI）；配置文件 ACL 限制 |
| 中心链路窃听或伪造 | 可选 `wss` + 可选 Bearer/短期令牌；本机模式不启用中心出口 |
| 恶意插件 | 插件签名校验、独立进程、最小权限运行；插件清单白名单 |
| 日志泄漏业务数据 | 默认只记录元数据；原始载荷日志仅在调试开关开启时记录并设置保留期 |
| 命令滥用 | 事务命令按通道白名单限制（仅允许配置的查询指令），记录审计 |
| 恶意或畸形数据文件 | 文件大小/记录数/解析时间上限；解析器隔离进程；失败文件进入错误目录，不自动执行 |
| 文件路径穿越/符号链接 | 输入、归档、错误目录必须位于配置根目录内；解析前后校验真实路径，拒绝逃逸链接 |
| 第三方解析器不可信 | 插件签名校验、独立进程、最小权限账户运行、资源配额与崩溃隔离 |
| 多设备串扰/越权 | 数据与命令按 `deviceId` 路由，订阅按设备过滤；单设备数据不得广播到其他设备 |

- 本地管理 API 与数据 WebSocket 使用独立路径；单机模式下管理 API 匿名开放，数据 WebSocket 由 Origin 白名单限制，令牌可选。
- 当前本机模式不启用 TLS。页面为 HTTPS 时，浏览器对 `ws://127.0.0.1` 的混合内容可能被阻止；此时使用本机 HTTP 页面、桌面壳，或后续增加本机受信证书的 `wss`。

## 9. 部署与运维

- 发布形态：`dotnet publish` 单文件自包含 `win-x64`（可裁剪），同时提供框架依赖版用于内网统一运行时环境。
- 安装形态：当前为 WinUI3 桌面应用（原生 Win32 `Shell_NotifyIcon` 托盘，关闭窗口驻留托盘）；Windows 服务形态待实施。
- 自启动：Windows 服务与登录自启待实施。
- 升级：P2 引入签名升级包与中心下发；升级前备份配置与 spool，失败自动回滚上一版本。
- 日志：结构化 JSON 行，按天/大小滚动，本地保留 14 天；关键事件包括连接状态、配置变更、事务结果、spool 水位。
- 可观测：每 30 秒向中心上报心跳（`agentId`、当前 `hostName`、各设备状态、最后数据时间、队列水位、丢弃计数）；本地管理 API 提供同样指标。
- 文件型设备：共享目录使用服务账户授权，网络共享断线按 `waiting` 处理并周期补偿扫描；归档清理与磁盘水位纳入监控。
- 容量与性能预算：单 Agent 支持 16 个设备通道（其中使用解析插件的设备不超过 4 个）；典型场景为 14 台低频设备 + 2 台 100 帧/秒设备，聚合不超过 500 帧/秒、单帧 1 KiB 时，主进程与插件进程合计内存不超过 600 MiB，本机转发附加延迟不超过 50 ms，CPU 平均不超过单核 30%。单设备队列隔离，不因一台设备卡顿拖慢其他设备。
- Linux 支持（P3）：以 systemd 服务发布，串口设备按 `/dev/serial/by-id` 绑定；不作为首期验收范围。

## 10. 技术选型

| 选择 | 说明 |
| --- | --- |
| .NET 10 Worker Service | 与仓库技术栈一致；`Microsoft.Extensions.Hosting` 提供服务生命周期、配置、日志与 Windows 服务集成 |
| `System.IO.Ports` | 串口读写；注意 Windows 独占与 Linux 设备命名差异 |
| `FileSystemWatcher` + 周期扫描 | 文件通道监听；网络共享与事件丢失场景由补偿扫描兜底 |
| SHA-256 + 文件状态文件 | 文件去重与断点恢复，不引入嵌入式数据库 |
| stdio JSON-RPC | 解析插件与 SDK 插件的进程间通信，无固定端口冲突 |
| 内置 CSV 解析 | 简单 CSV 按配置表头映射；复杂或专有格式走插件 |
| ASP.NET Core Kestrel（仅本机） | 承载本机 WebSocket 与管理 API，不对外网卡开放 |
| `System.Threading.Channels` | 每设备有界队列与异步管道，天然支持背压、取消与设备间隔离 |
| System.Text.Json | 消息信封与配置文件序列化，源生成器降低开销 |
| JSONL 文件 spool | 无额外依赖、可人工排查、按段删除；不引入嵌入式数据库 |
| xUnit | 帧切分、解析、事务匹配、spool 回放的单元与集成测试 |

备选方案对比：

- **Node-RED**：串口与 WebSocket 节点齐全，但需要 Node 运行时和额外运维，请求/应答事务、Windows 服务化、静默升级需自行补齐。
- **Telegraf**：采集能力强，但输出模型偏时序数据库，命令事务与自定义帧解析扩展成本高。
- **自研**：与 .NET 技术栈一致，可控分发与安全模型，长期维护成本最低。

## 12. 与平台集成

- **中心网关**（后续在 `api` 新增模块或独立服务，本设计只定义职责）：设备凭据认证、按 `agentId + deviceId` 注册多台设备与在线状态、消息去重与入库、按设备类型向业务模块转发、原始帧留存策略。
- **边界**：Agent 只负责采集与转发，不直接写数据库；业务模块通过 Contracts 端口消费设备数据，审批/检验等业务逻辑不进入 Agent。
- **前端契约**：前端统一对接「设备数据客户端」抽象（`{deviceId, deviceType, channelId, 值, 单位, 时间戳, 稳定标志, 状态}`），传输层可选本机 WebSocket 或平台 SignalR；页面不感知串口细节，并按设备订阅。
- **设备台账**：平台维护设备台账，`deviceId` 使用台账中的设备编号/编码并与 `agentId` 关联；`channelId` 是采集管线标识；同一上位机可登记多台设备，工位页面按当前工位解析可用设备。
- **测试类型区分**：`deviceType` 只表达采集类别（`pullTest`/`dieShear`/`scale` 等），具体业务检验类型由平台映射；一台上位机的多台设备数据不得合并为同一条记录。
- **文件型设备**：原始文件可按平台文件存储能力归档留存；Agent 上传解析记录、文件元数据（名称、大小、SHA-256）与可选原文件，检验记录通过 `sourceRef` 回溯到文件与记录序号。
- **典型链路**：每台设备 → Agent 对应通道 → 中心网关 → 业务模块生成检验记录 → Web 按设备展示；原始帧按配置留存用于追溯。

## 13. 典型场景

### 13.1 电子秤（持续输出）

- 串口 9600/8/N/1，以 `\r\n` 分隔，周期性输出 `ST,GS,+0012.345kg`。
- Codec 使用分隔符 + 正则，解析出数值、单位与稳定标志；Agent 直通转发，稳定判定与防抖由页面或业务层完成。
- 本机页面通过 `ws://127.0.0.1` 订阅，操作员录入时只取稳定值；中心出口按需开启留痕。

### 13.2 焊线拉力测试机（请求/应答）

- 设备可能提供串口指令集、私有 TCP 协议或 Windows SDK；先用串口助手/网络抓包确认帧格式、校验与应答规则。
- 若为标准串口协议：配置 `tcpClient`/`serial` + 定长或长度前缀 Codec，事务命令按「条码查询 → 触发测试 → 读取结果」编排。
- 若只提供 SDK：编写 `plugin`，独立进程封装厂商 DLL，对 Agent 暴露统一的读写接口；位数（x86/x64）与授权方式在插件清单声明。
- 结果经中心网关进入 QMS，原始帧留存用于质量追溯。

### 13.3 串口服务器 / 单设备串口链路

- 电子秤或仪表经串口服务器转以太网时，一个 TCP 连接对应一台设备，Agent 以 `tcpClient` 连接；Modbus RTU over TCP 由 P2 的 `modbusRtu` 编解码器轮询读取。
- 若现场是一条 RS-485 总线挂多台设备，由串口服务器/前置采集器按设备拆成独立连接后再接入 Agent；核心模型不做帧级 `demux`。

### 13.4 数据文件型设备

- 设备在每批次、每片或每次测试结束后导出 CSV/TXT 文件到设备专属目录（本机或网络共享），无实时接口。
- 文件通道按完成判定读取，内置 CSV 解析按表头映射字段；专有二进制、复杂 XML 或 Excel 使用解析插件。
- 示例：

```json
{ "id": "pt-02-file", "deviceId": "PT-002", "deviceType": "pullTest",
  "sourceRef": "dir-pulltest",
  "codec": { "type": "csv", "csvDelimiter": ",", "encoding": "utf-8", "hasHeader": true,
             "columns": { "sampleId": "Sample", "force": "ForceN", "time": "Time" } },
  "sinks": ["center"] }
```

- `sourceRef` 指向 3.2 中的文件源；一个目录只对应一台设备，多台设备分别配置目录，不共用目录猜测归属。
- 专属格式切换为 `"codec": { "type": "plugin", "pluginId": "vendor-pulltest", "version": "1.0.0" }`，其余设备通道配置不变。

### 13.5 多设备上位机（拉力 + Die 推力 + 文件）

- 一台上位机同时连接：COM3 焊线拉力测试机（指令/应答）、COM4 上的 Die 焊接推力测试机、另一台拉力机的专属 CSV 导出目录。
- 三条设备通道分别使用内置正则解析、厂商解析插件和内置 CSV 解析；共用中心 WebSocket 出口，但各自维护设备序号、队列与 spool 分区。
- 任一设备拔线、解析失败或插件崩溃只影响该设备；页面按 `deviceId`/`deviceType` 订阅当前工位需要的设备。

## 15. 验收与测试矩阵

| 场景 | 预期 |

| 磁盘写满 | 中心出口 `faulted`，本机实时出口继续工作，告警可见 |
| 100 帧/秒 × 2 设备 + 20 帧/秒 × 14 设备 | 满足第 9 节性能预算，无持续积压 |

| 一台设备拔线/离线 | 仅该设备 `waiting`/`degraded`，其他设备持续采集 |
| 一条 TCP/串口断线重连 | 仅对应设备 `waiting` → `connected`，其他设备持续采集 |
| 畸形文件 | 进入错误目录并告警，其他设备不受影响 |
| 单设备插件崩溃 | 仅该设备通道受影响并自动恢复，其他设备不中断 |
| 非白名单 Origin / 错误令牌 | 拒绝连接，不泄露数据 |
| 中心网关重启 | Agent 自动重连，补传期间实时数据不中断写入 spool |
| 系统休眠/唤醒 | 连接恢复并重新打开串口，状态事件完整 |
