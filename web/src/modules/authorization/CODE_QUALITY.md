# 授权模块代码质量指南

## 代码一致性检查清单

### 1. 命名规范

- [ ] 组件名使用 PascalCase（如 `UserEditModal.vue`）
- [ ] 文件名与组件名一致
- [ ] Composable 使用 `use` 前缀（如 `useUserData.ts`）
- [ ] 类型定义文件使用 `Models` 后缀（如 `userModels.ts`）
- [ ] 常量使用 UPPER_SNAKE_CASE
- [ ] 变量和函数使用 camelCase

### 2. 文件结构

每个实体的标准文件结构：
```
entity/
├── index.vue              # 主页面
├── EntityTableView.vue    # 表格视图
├── EntityCardView.vue     # 卡片视图
├── EntityEditModal.vue    # 编辑弹窗
├── EntityDetailModal.vue  # 详情弹窗
└── useEntityData.ts       # 数据管理 composable
```

### 3. API 层一致性

- [ ] 所有 API 模块遵循相同的结构
- [ ] 使用统一的类型定义（QueryParams, PagedResult）
- [ ] 错误处理一致
- [ ] 使用集中式请求工具

### 4. Composable 模式

每个 composable 应包含：
- [ ] loading 和 submitting 状态
- [ ] 数据列表和分页信息
- [ ] 搜索和排序状态
- [ ] CRUD 操作方法
- [ ] 统一的错误处理

### 5. 组件 Props 和 Emits

- [ ] 使用 TypeScript 接口定义 Props
- [ ] 使用 TypeScript 定义 Emits
- [ ] Props 有合理的默认值
- [ ] 事件命名清晰且一致

### 6. 样式规范

- [ ] 使用 scoped 样式
- [ ] 使用 CSS 变量（如 `var(--n-color)`）
- [ ] 移动端适配使用媒体查询
- [ ] 避免硬编码颜色和尺寸

### 7. 响应式设计

- [ ] 使用 `useResponsive` hook
- [ ] 表格和卡片视图自动切换
- [ ] 模态框在移动端适配
- [ ] 触摸友好的交互

### 8. 可访问性

- [ ] 语义化 HTML
- [ ] ARIA 标签
- [ ] 键盘导航支持
- [ ] 焦点管理

### 9. 性能优化

- [ ] 使用防抖处理搜索
- [ ] 取消重复请求
- [ ] 懒加载大型组件
- [ ] 合理使用 v-memo

### 10. 错误处理

- [ ] 区分取消错误和真实错误
- [ ] 显示用户友好的错误消息
- [ ] 记录错误日志
- [ ] 提供错误恢复机制

## 重构建议

### 1. 提取公共逻辑

如果多个组件有相似的逻辑，考虑：
- 创建 composable
- 创建工具函数
- 创建高阶组件

### 2. 简化复杂组件

如果组件超过 300 行，考虑：
- 拆分为子组件
- 提取逻辑到 composable
- 使用插槽提高灵活性

### 3. 优化数据流

- 使用 props 向下传递数据
- 使用 emits 向上传递事件
- 避免深层 prop drilling
- 考虑使用 provide/inject

### 4. 改进类型定义

- 使用 interface 而非 type（除非需要联合类型）
- 避免使用 any
- 使用泛型提高复用性
- 导出所有公共类型
