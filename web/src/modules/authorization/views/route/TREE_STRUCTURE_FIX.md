# 路由管理树形结构优化

## 问题
1. **分页数据不完整**：前端用分页数据构建树，导致父子节点可能分散在不同页，树结构断裂
2. **展开状态混乱**：点击展开一行，其他行也跟着展开

## 解决方案
**后端智能分页 + 完整树形结构**：
- 分页只针对**根路由**（ParentId 为空）
- 每个根路由的**所有子孙节点**自动包含
- 保证树形结构完整，不会因分页断裂

### 后端优化
1. **新增 `GetRoutesWithMetaPagedAsync()` API**
   - 只对根路由进行分页计数和查询
   - 自动加载每个根路由的完整子树
   - 后端按 `meta.order` 排序
   - 支持关键词搜索和模块过滤

2. **保留 `GetRoutesWithMetaAsync()` API**
   - 无分页，返回所有路由的完整树形结构
   - 用于需要全量数据的场景

### 前端修改
1. **useRouteData.ts**
   - 使用 `routeApi.getRoutesWithMetaPaged()` 获取分页树形数据
   - 恢复分页逻辑（page、pageSize）
   - 移除前端过滤逻辑（由后端处理）

2. **RouteTableView.vue**
   - 恢复分页组件
   - 添加 `:row-key` 确保展开状态正确

3. **RouteCardView.vue**
   - 恢复分页功能
   - 扁平化显示当前页的路由树

## 优势
- ✅ 树形结构完整，不会因分页断裂
- ✅ 展开状态独立，不会互相影响
- ✅ 支持分页，性能更好（只查询需要的根路由）
- ✅ 后端统一排序和过滤，逻辑集中
- ✅ 分页计数准确（只计根路由数量）

## 示例
假设有以下路由结构：
```
根路由1
  ├─ 子路由1-1
  └─ 子路由1-2
根路由2
  ├─ 子路由2-1
  │   └─ 孙路由2-1-1
  └─ 子路由2-2
根路由3
```

**分页设置：每页2条**
- 第1页：根路由1（含所有子节点）+ 根路由2（含所有子孙节点）
- 第2页：根路由3
- 总计：3条（只计根路由）

这样既保证了树形结构完整，又实现了高效分页。
